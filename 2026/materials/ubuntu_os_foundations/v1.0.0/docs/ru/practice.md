## Сначала подключитесь к Ubuntu

После первоначальной настройки AWS Academy Learner Lab откройте CloudShell в консоли AWS. В CloudShell подключитесь к своему учебному серверу Ubuntu:

```bash
ssh jdu-ubuntu
```

P0–P5 выполняются на подключённом сервере Ubuntu. В P6 для действий в CloudShell и Ubuntu место выполнения указано в шагах.

## 0. Общие правила

P0–P6 предназначены для тренировки. P0 — первое пошаговое наблюдение за ОС. P1–P6 используют другие каталоги, учётные записи, группы, службы и порты, чем M1–M6. M7 — итоговое задание, поэтому отдельной практики для него нет.

В каждом P сначала дано задание, затем пример решения. Можно попробовать решить задание без подсказок или сразу работать по шагам. P и M оцениваются раздельно: PASS в P не означает PASS в M.

В Ubuntu выполните команду и убедитесь, что показано `ssm-user`:

```bash
id -un
```

Если показано другое имя, один раз выполните `exit` и проверьте снова:

```bash
exit
id -un
```

Перед каждым действием переходите в указанный рабочий каталог, затем подтверждайте текущее место через `pwd`.

Проверку на стороне Ubuntu запускайте как `ssm-user`. В P6 проверку стороны CloudShell выполняйте в CloudShell:

```bash
jdu-check P1
```

Проверка оценивает конечное состояние. Наблюдение и промежуточные действия могут не оцениваться. Результат автоматически отправляется преподавателю. Даже если отправка не удалась, PASS/FAIL виден в Ubuntu или CloudShell.

Сброс нужен только для начала упражнения заново:

```bash
jdu-reset P1
```

## P0. Среда и ОС

### Что изучаем

- Отличать сведения об ОС Ubuntu от сведений о ядре Linux.
- На работающем сервере определять текущего пользователя, имя хоста и процесс с PID 1.
- Записывать результаты команд в файл, сохранять, проверять и сдавать его.

### Задание

На своём учебном сервере Ubuntu определите шесть значений и запишите их в `~/jdu-lab/p0/observation.env`. Это прежнее M0, перенесённое в пошаговое упражнение P0. Не копируйте значения из примера или у другого студента: используйте вывод именно своего сервера. Проверьте шесть пунктов командой `jdu-check P0`.

### Пример решения (пошаговые действия)

#### Шаг 1. Проверьте сервер и пользователя

Как указано в начале документа, выполните в CloudShell `ssh jdu-ubuntu`. Все следующие действия выполняйте в Ubuntu.

```bash
# Перейдите в домашний каталог.
cd ~
# Покажите текущий каталог.
pwd
# Покажите имя текущего пользователя.
id -un
```

Убедитесь, что `id -un` показывает `ssm-user`. Это будущее значение `USER_NAME`. Записывайте следующие результаты для себя.

#### Шаг 2. Определите тип и версию ОС

```bash
# Покажите тип и версию ОС.
cat /etc/os-release
```

Значение `ID=` запишите как `OS_ID`, а `VERSION_ID=` — как `OS_VERSION_ID`. Это не поля `NAME` или `PRETTY_NAME`. Если значение окружено кавычками, записывайте только содержимое без кавычек.

#### Шаг 3. Определите версию ядра Linux

```bash
# Покажите номер выпуска ядра Linux.
uname -r
```

Опция `-r` показывает release ядра. Запишите всю выведенную строку как `KERNEL_RELEASE`. Версия ОС и версия ядра — разные сведения.

#### Шаг 4. Узнайте имя процесса с PID 1

```bash
# Покажите имя процесса с PID 1.
cat /proc/1/comm
```

В `/proc` доступны сведения о работающей системе. `1` — номер процесса (PID), а файл `comm` содержит его имя. Запишите результат как `PID1_COMM`.

#### Шаг 5. Проверьте пользователя и имя хоста

```bash
# Покажите имя текущего пользователя.
id -un
# Покажите имя хоста сервера.
hostname
```

Первый результат — `USER_NAME`, второй — `HOST_NAME`. Имя хоста обозначает сервер; это не имя пользователя и не Server ID для отправки результатов.

#### Шаг 6. Создайте файл наблюдений

```bash
# Перейдите в домашний каталог.
cd ~
# Создайте рабочий каталог P0.
mkdir -p jdu-lab/p0
# Перейдите в рабочий каталог P0.
cd jdu-lab/p0
# Покажите текущий каталог.
pwd
# Отредактируйте файл наблюдений.
nano observation.env
```

В `nano` введите шесть строк ниже. Справа от каждого `=` поставьте значение, полученное на вашем сервере. Это содержимое файла, а не команды для выполнения:

```text
OS_ID=
OS_VERSION_ID=
KERNEL_RELEASE=
PID1_COMM=
USER_NAME=
HOST_NAME=
```

Каждый ключ занимает одну строку. Не добавляйте пробелы вокруг `=` и кавычки вокруг значений. Сохраните через `Ctrl+O`, подтвердите имя `observation.env` клавишей `Enter`, затем выйдите через `Ctrl+X`.

#### Шаг 7. Проверьте сохранённый файл

```bash
# Покажите текущий каталог.
pwd
# Проверьте наличие и права файла наблюдений.
ls -l observation.env
# Покажите шесть записанных полей.
cat observation.env
```

У всех шести строк должны быть значения из шагов 1–5. Пустые или неверные значения исправьте через `nano observation.env` и снова сохраните.

#### Шаг 8. Проверьте и сдайте результат

```bash
# Проверьте, под каким пользователем выполняется оценка.
id -un
# Проверьте готовность P0.
jdu-check P0
```

Результат `6 / 6 checks cleared` и шесть `PASS` означают, что P0 завершено. При `FAIL` проверьте указанный пункт на своём сервере, исправьте файл и запустите проверку снова.

`RESULT` — оценка задания, `REPORT` — отправка преподавателю. Если отправка не удалась, не удаляйте файл и не сбрасывайте упражнение. Проверьте связь и регистрацию, затем повторите команду.

#### Шаг 9. Перейдите к следующему упражнению

```bash
# Вернитесь в домашний каталог перед следующим упражнением.
cd ~
```

Продолжайте с P1. Выполняйте `exit` только если хотите вернуться в CloudShell. При первом выполнении P0 сброс не нужен. Для повторного прохождения с удалением записи используйте в Ubuntu `jdu-reset P0`.

## P1. Оболочка, путь, файл и текст

### Что изучаем

- Различие между домашним и рабочим каталогами.
- Создание каталогов.
- Копирование файлов.
- Сохранение нужных строк из журнала.

### Задание

В `~/jdu-lab/p1/inbox` находятся файл настройки и журнал. Каталог `~/jdu-lab/p1/practice01` ещё не готов; в нём остались ненужные файлы `.tmp`. Приведите его к следующему состоянию:

1. Создайте внутри `practice01` каталоги `config`, `logs` и `notes`.
2. Скопируйте `inbox/config/training.conf` в `practice01/config/training.conf`, а `inbox/logs/practice.log` в `practice01/logs/practice.log`. Не меняйте содержимое оригиналов и копий.
3. Удалите все файлы `.tmp` внутри `practice01`, не удаляя другие файлы.
4. Владельцем каталогов и файлов внутри готового `practice01` должен быть управляющий пользователь Ubuntu `ssm-user`.
5. Сохраните в `practice01/notes/warnings.txt` только строки скопированного журнала, содержащие `WARN`, без номеров строк.
6. Сохраните в `practice01/notes/recent.txt` последние четыре строки того же журнала в исходном порядке.

Проверьте готовое состояние через `jdu-check P1`. После шести PASS упражнение завершено.

### Пример решения (пошаговые действия)

#### Шаг 1. Перейдите в домашний каталог

```bash
# Перейдите в домашний каталог.
cd ~
# Покажите текущий каталог.
pwd
```

Убедитесь, что показано `/home/ssm-user`.

#### Шаг 2. Перейдите в каталог P1

```bash
# Перейдите в рабочий каталог P1.
cd ~/jdu-lab/p1
# Покажите текущий каталог.
pwd
# Покажите исходные файлы и незавершённый результат деревом.
tree
```

Найдите `inbox` и незавершённый `practice01`.

#### Шаг 3. Создайте нужные каталоги

```bash
# Перейдите в рабочий каталог P1.
cd ~/jdu-lab/p1
# Создайте каталог для файла настроек.
mkdir -p practice01/config
# Создайте каталог для журнала.
mkdir -p practice01/logs
# Создайте каталог для файла результата.
mkdir -p practice01/notes
# Покажите созданную структуру.
tree practice01
```

#### Шаг 4. Скопируйте файл настройки

Сначала перейдите в каталог назначения:

```bash
# Перейдите в каталог назначения настроек.
cd ~/jdu-lab/p1/practice01/config
# Проверьте текущий каталог.
pwd
# Скопируйте исходный файл настроек в текущий каталог.
cp ../../inbox/config/training.conf .
# Покажите скопированный файл.
ls -l
```

`.` означает текущий каталог.

#### Шаг 5. Скопируйте файл журнала

```bash
# Перейдите в каталог назначения журнала.
cd ~/jdu-lab/p1/practice01/logs
# Проверьте текущий каталог.
pwd
# Скопируйте исходный журнал в текущий каталог.
cp ../../inbox/logs/practice.log .
# Покажите скопированный файл.
ls -l
```

#### Шаг 6. Найдите и удалите временные файлы

Перейдите в `practice01` и осмотрите каталог до удаления:

```bash
# Перейдите в каталог, который нужно завершить.
cd ~/jdu-lab/p1/practice01
# Проверьте текущий каталог.
pwd
# Покажите структуру файлов до удаления.
tree
```

Найдите в `staging` файлы `training.conf.tmp` и `practice.log.tmp`. Теперь выполните поиск по тому же условию:

```bash
# Найдите только файлы .tmp в текущем каталоге и ниже.
find . -type f -name '*.tmp' -print
```

`.` — начальный каталог поиска, `-type f` выбирает обычные файлы, `-name '*.tmp'` — имена с окончанием `.tmp`, `-print` показывает пути. Кавычки не дают оболочке заранее раскрыть `*.tmp`. Сверьте найденные пути с выводом `tree`. Убедившись, что это именно два ненужных файла, удалите их по точным путям:

```bash
# Удалите два проверенных ненужных временных файла.
rm staging/training.conf.tmp staging/practice.log.tmp
# Проверьте структуру после удаления.
tree
```

Два файла `.tmp` исчезли, а `config/training.conf` и `logs/practice.log` остались.

#### Шаг 7. Сохраните строки WARN

Перейдите в каталог результата `notes`:

```bash
# Перейдите в каталог для файла результата.
cd ~/jdu-lab/p1/practice01/notes
# Проверьте текущий каталог.
pwd
# Покажите строки журнала с WARN на экране.
grep 'WARN' ../logs/practice.log
```

Убедитесь, что показаны только строки с `WARN`. Добавьте `>` к той же команде, чтобы сохранить результат. `>` перенаправляет вывод с экрана в файл и перезаписывает уже существующий файл с тем же именем:

```bash
# Сохраните строки WARN в warnings.txt.
grep 'WARN' ../logs/practice.log > warnings.txt
# Покажите сохранённый результат.
cat warnings.txt
```

Сравните сохранённые строки с теми, которые были показаны на экране.

#### Шаг 8. Сохраните последние четыре строки

```bash
# Перейдите в каталог для файла результата.
cd ~/jdu-lab/p1/practice01/notes
# Покажите последние четыре строки журнала на экране.
tail -n 4 ../logs/practice.log
```

Убедитесь, что показаны четыре последние строки в исходном порядке. Затем сохраните тот же результат:

```bash
# Сохраните последние четыре строки в recent.txt.
tail -n 4 ../logs/practice.log > recent.txt
# Покажите сохранённый результат.
cat recent.txt
```

Проверьте сохранённые четыре строки через `cat`.

#### Шаг 9. Проверьте результат целиком

```bash
# Вернитесь в рабочий каталог P1.
cd ~/jdu-lab/p1
# Покажите готовую структуру каталогов.
tree practice01
# Проверьте готовность P1.
jdu-check P1
```

Когда все шесть пунктов покажут PASS, переходите к M1.

## P2. Пользователи, группы, права и setgid

### Что изучаем

- Проверка основной и дополнительных групп.
- Настройка групповых прав на общий каталог.
- Наследование группы новым файлом с помощью setgid.

### Задание

Разделите возможности автора и читателя в общем каталоге `/srv/jdu-practice-share`. Сначала `jdupracticeviewer` ошибочно входит в дополнительную группу `practiceops`, а `jdupracticewriter` в неё не входит. Владелец, группа и права каталога и `GUIDE.txt` ещё не соответствуют требуемым.

1. Добавьте `jdupracticewriter` в дополнительную группу `practiceops`, а `jdupracticeviewer` удалите из неё.
2. Установите для `/srv/jdu-practice-share` владельца и группу `root:practiceops`, режим `2775`, чтобы новые файлы наследовали группу каталога.
3. Установите для `GUIDE.txt` владельца и группу `root:practiceops`, режим `664`.
4. Переключитесь из `ssm-user` в `jdupracticewriter` и создайте `writer-created.txt` в общем каталоге. Убедитесь, что группа нового файла — `practiceops`.
5. Вернитесь к `ssm-user` и переключитесь в `jdupracticeviewer`. Проверьте, что `GUIDE.txt` можно читать, но создать новый файл в общем каталоге нельзя.

После действий под другими пользователями вернитесь к `ssm-user` и выполните `jdu-check P2`. Шесть проверок охватывают членство в группе, каталог, файл, наследование группы и доступ читателя.

### Пример решения (пошаговые действия)

#### Шаг 1. Проверьте управляющего пользователя

```bash
# Перейдите в домашний каталог.
cd ~
# Покажите имя текущего пользователя.
id -un
# Покажите ID текущего пользователя и его группы.
id
```

#### Шаг 2. Проверьте начальное членство в группе

```bash
# Покажите запись общей группы.
getent group practiceops
# Проверьте группы пользователя записи.
id jdupracticewriter
# Проверьте группы пользователя просмотра.
id jdupracticeviewer
```

Изначально `jdupracticeviewer` входит в `practiceops`, а `jdupracticewriter` — нет.

#### Шаг 3. Исправьте членство

```bash
# Перейдите в домашний каталог.
cd ~
# Добавьте пользователя записи в общую группу.
sudo usermod -aG practiceops jdupracticewriter
# Удалите пользователя просмотра из общей группы.
sudo gpasswd -d jdupracticeviewer practiceops
# Покажите общую группу после изменений.
getent group practiceops
# Проверьте членство пользователя записи в группах.
id jdupracticewriter
# Проверьте членство пользователя просмотра в группах.
id jdupracticeviewer
```

#### Шаг 4. Настройте общий каталог

```bash
# Перейдите в /srv.
cd /srv
# Покажите текущий каталог.
pwd
# Покажите исходные права самого общего каталога.
ls -ld jdu-practice-share
```

Посмотрите начальные права, владельца и группу каталога. В `ls -ld` опция `-d` показывает сам каталог, а не его содержимое. Сначала указаны права, затем после числа ссылок — владелец и группа.

```bash
# Измените владельца и группу общего каталога.
sudo chown root:practiceops jdu-practice-share
# Проверьте изменение владельца и группы.
ls -ld jdu-practice-share
# Установите права 2775 с наследованием группы.
sudo chmod 2775 jdu-practice-share
# Проверьте символ s для setgid и права доступа.
ls -ld jdu-practice-share
```

После `chown` владелец и группа должны быть `root practiceops`; после `chmod` права должны выглядеть как `drwxrwsr-x`. Буква `s` в позиции исполнения группы означает setgid: новый файл наследует группу каталога.

#### Шаг 5. Настройте GUIDE.txt

Перейдите в каталог файла:

```bash
# Перейдите в общий каталог.
cd /srv/jdu-practice-share
# Покажите текущий каталог.
pwd
# Покажите исходные права GUIDE.txt.
ls -l GUIDE.txt
```

Перед изменением посмотрите начальные права, владельца и группу файла:

```bash
# Измените владельца и группу GUIDE.txt.
sudo chown root:practiceops GUIDE.txt
# Проверьте владельца и группу.
ls -l GUIDE.txt
# Разрешите владельцу и группе чтение и запись.
sudo chmod 664 GUIDE.txt
# Проверьте окончательные права файла.
ls -l GUIDE.txt
```

Итог: `root practiceops` и `-rw-rw-r--`. Владелец и группа могут читать и записывать, остальные — только читать.

#### Шаг 6. Переключитесь на writer и создайте файл

```bash
# Вернитесь в домашний каталог.
cd ~
# Переключитесь в оболочку пользователя записи.
sudo su - jdupracticewriter
# Проверьте имя пользователя после переключения.
id -un
# Проверьте группы после переключения.
id
# Перейдите в общий каталог.
cd /srv/jdu-practice-share
# Проверьте текущий каталог.
pwd
# Создайте файл от имени пользователя записи.
printf '%s\n' 'guided writer file' > writer-created.txt
# Проверьте группу-владельца созданного файла.
ls -l writer-created.txt
# Выйдите из оболочки пользователя записи.
exit
# Убедитесь, что вернулись к управляющему пользователю.
id -un
```

В конце должно появиться `ssm-user`.

#### Шаг 7. Проверьте чтение и запись под viewer

```bash
# Вернитесь в домашний каталог.
cd ~

### Задание

REMOTE_HOST=фактическое имя хоста

```

1. Запишите в `~/jdu-lab/p6/practice-source.txt` в CloudShell ровно строку `JDU SSH guided transfer`.
