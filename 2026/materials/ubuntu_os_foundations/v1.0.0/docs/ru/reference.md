## Термины

## Основные команды

| Задача | Команда и параметры | Риск или частая ошибка | Проверка результата |
| --- | --- | --- | --- |
| Текущий каталог | `pwd` | Не судите только по строке приглашения. | Сопоставьте путь с хостом и пользователем. |
| Переход | `cd PATH`, `cd ..`, `cd ~` | Относительный путь зависит от текущего каталога. | `pwd`. |
| Список | `ls -la`, `ls -ld DIR` | `-l DIR` показывает содержимое, `-ld DIR` — сам каталог. | При необходимости `stat`, `tree`. |
| Дерево каталогов | `tree PATH` | Не показывает всё содержимое файлов и все подробности прав. | Сопоставьте с `ls -l`. |
| Создание каталога | `mkdir -p PATH` | Не создайте ошибочное дерево из-за неверного пути. | `tree`, `ls -ld`. |
| Копирование | `cp SOURCE DEST` | Не перепутайте источник и назначение; берегитесь перезаписи. | `cat`, `sha256sum`. |
| Перемещение или переименование | `mv SOURCE DEST` | Возможна непреднамеренная перезапись. | `ls`. |
| Удаление | `rm FILE` | Обычно нет «корзины»; в заданиях не используйте `rm -rf`. | Перед удалением `pwd`, `ls`; после него убедитесь в отсутствии. |
| Редактирование | `nano FILE` | Проверьте путь и сохранение. | `Ctrl+O`, `Enter`, `Ctrl+X`, затем `cat`. |
| Чтение | `cat FILE`, `less FILE` | Не выводите через `cat` огромный или двоичный файл. | Выйдите из `less` клавишей `q`. |
| Поиск строк | `grep [-F] PATTERN FILE` | `-n` добавляет номер строки; не включайте его, если нужна исходная строка. | Сверьте строки и код завершения. |
| Последние строки | `tail -n N FILE` | Здесь `-n` означает число строк, не то же, что у `grep`. | Проверьте число и порядок. |
| Запись stdout | `>`, `>>` | `>` обнуляет существующий файл; не указывайте входной файл и выходной как один и тот же. | `cat`, `wc -l`. |
| Конвейер | `\|` | Через него проходит stdout, но обычно не stderr. | Сначала проверьте каждую команду отдельно. |
| Пользователь и группы | `id [USER]`, `groups [USER]` | Различайте запись об аккаунте и группы работающего сеанса. | После нового входа выполните `id`. |
| База учётных записей | `getent passwd USER`, `getent group GROUP` | Список членов группы может не показывать тех, для кого она основная. | Сопоставьте с `id USER`. |
| Переключение пользователя | `sudo su - USER`, `exit` | Оболочки вкладываются друг в друга; учебные пользователи не имеют sudo. | После каждого перехода `id -un`, `pwd`. |
| Одна команда под другим пользователем | `sudo -u USER -- COMMAND` | Успех под root не доказывает успех под нужным пользователем. | Сразу проверьте `echo $?`. |
| Добавить в группу | `usermod -aG GROUP USER` | Без `-a` параметр `-G` может удалить другие дополнительные группы. | `id USER` и новый сеанс. |
| Удалить из группы | `gpasswd -d USER GROUP` | Соблюдайте порядок имени пользователя и группы. | `id USER`. |
| Сменить владельца и группу | `chown OWNER:GROUP PATH` | Рекурсивный `-R` может затронуть лишние файлы. | `stat -c '%U:%G %a %n'`. |
| Сменить режим | `chmod MODE PATH` | Не ставьте `777` без причины; `x` у файла и каталога различается. | `stat` и `test` под другим пользователем. |
| Процессы | `ps -e -o ...`, `ps -p PID -o ...` | Не копируйте пример PID из учебника. | Сверьте пользователя, команду и PID. |
| Сигнал процессу | `kill -TERM PID` | Убедитесь, что PID не пуст, не 0, не отрицателен и не 1. `pkill` не принимает PID в этом смысле. | `ps` или состояние службы. |
| Пакеты | `apt show NAME`, `sudo apt update`, `sudo apt install NAME` | Различайте обновление индекса (`update`) и пакетов (`upgrade`). Не обновляйте всю систему без связи с заданием. | `command -v`, `dpkg-query`. |
| Настройка службы | `systemctl cat UNIT` | Не редактируйте учебный юнит без задания. | Сверьте `User`, `WorkingDirectory`, `ExecStart`. |
| Состояние службы | `systemctl status/start/stop` | `active` не гарантирует исправность функции. | `is-active`, MainPID, `curl`. |
| Автозапуск | `systemctl enable/disable UNIT` | `start/stop` и `enable/disable` — разные действия. | `is-enabled`. |
| Главный PID | `systemctl status UNIT` | Читайте актуальное число после `Main PID:`; у остановленной службы поле может отсутствовать. | `ps -fp PID`. |
| Сокеты | `sudo ss -lntp` | Сверьте адрес, порт и PID. | Сопоставьте с Main PID. |
| HTTP | `curl -i URL`, при необходимости `--max-time` | Успешное TCP-соединение, статус HTTP и тело ответа — отдельные проверки. | Строка статуса, тело, код завершения. |
| Системный журнал | `sudo journalctl -u UNIT --no-pager -n N` | Не смешивайте старый запуск с текущим. | Найдите нужный путь запроса. |
| SSH | `ssh HOST`, `ssh HOST 'COMMAND'` | Отличайте псевдоним SSH от DNS-имени, локальную подстановку от удалённой; берегите ключ. | На адресате: `id -un`, `hostname`, `pwd`. |
| Передача SCP | `scp SOURCE DEST` | Не перепутайте направление и не перезапишите файл. | Сравните `sha256sum` на обеих сторонах и `stat` на адресате. |

## Как читать команду

Делите запись на имя команды, опции и объект действия. В `tail -n 4 practice.log` программа — `tail`, опция `-n` со значением `4` задаёт число строк, а `practice.log` — читаемый файл. Читайте части, разделённые пробелами, по порядку. Прописные `FILE`, `PATH` и `N` в справке — поясняющие обозначения; при выполнении заменяйте их настоящим именем, путём или числом.

Опция меняет действие команды. Краткая форма часто состоит из дефиса и буквы, например `-u`, длинная — из двух дефисов и слова, например `--user`. Не у каждой команды есть обе формы. У `find -name` слово следует после одного дефиса. Можно использовать английское значение как подсказку, но проверять точное действие нужно в справке конкретной команды.

### Запоминайте через английские слова

Слова ниже помогают запомнить команды, но не все являются официальной исторической расшифровкой их названия. `find` и `tail` — обычные английские слова.

| Команда | Английская подсказка | Что делает |
| --- | --- | --- |
| `pwd` | print working directory | Показывает рабочий каталог. |
| `cd` | change directory | Меняет рабочий каталог. |
| `ls` | list | Показывает список имён. |
| `mkdir` | make directory | Создаёт каталог. |
| `cp` | copy | Копирует: сначала источник, затем назначение. |
| `mv` | move | Перемещает или переименовывает в том же каталоге. |
| `rm` | remove | Удаляет указанный файл. |
| `cat` | concatenate | Соединяет и выводит содержимое файлов; работает и с одним файлом. |
| `tree` | tree | Показывает структуру каталогов в виде дерева. |
| `find` | find | Ищет объект по условиям, проходя каталоги. |
| `grep` | global / regular expression / print (`g/re/p`) | Ищет строки внутри файла, в отличие от `find` для имён объектов. |
| `tail` | tail | Показывает конец файла. |
| `id` | identity / identifier | Показывает идентификаторы пользователя и групп. |
| `chown` | change owner | Меняет владельца. |
| `chmod` | change mode | Меняет режим прав доступа. |
| `ssh` | Secure Shell | Защищённо соединяет с другим компьютером. |

### Разберите id -un по частям

Без опций `id` показывает UID, GID и группы. Сравните:

```bash
id
id -u
id -u -n
id -un
```

`-u` соответствует `--user` и выводит только эффективный UID. `-n` соответствует `--name` и заменяет номер именем. Поэтому `id -u -n` и `id -un` означают одно и то же; после подключения к нашему Ubuntu они показывают `ssm-user`.

**Одного `id -n` недостаточно:** нужно указать, какой идентификатор переводить в имя. Используйте `-n` вместе с `-u`, `-g` либо `-G`. `id -gn` показывает имя эффективной группы, `id -Gn` — имена всех групп. Проверяйте не только английскую подсказку, но и допустимые сочетания.

### Одна буква у разных команд означает разное

| Пример | Значение опции | Результат |
| --- | --- | --- |
| `id -un` | `-u` — user, `-n` — name | Имя эффективного пользователя. |
| `grep -n 'WARN' practice.log` | `-n` — `--line-number` | Номер перед каждой найденной строкой. |
| `tail -n 4 practice.log` | `-n` — `--lines`, значение `4` | Последние четыре строки. |
| `ls -la` | `-l` — длинный формат, `-a` — все записи | Подробный список, включая скрытые файлы. |
| `mkdir -p logs/archive` | `-p` — `--parents` | Создаёт недостающие родительские каталоги. |
| `grep -F 'WARN' practice.log` | `-F` — `--fixed-strings` | Ищет буквальную строку, не регулярное выражение. |
| `chown -R USER DIR` | `-R` — `--recursive` | Меняет владельца также внутри каталога. |

Краткие опции иногда объединяются, как в `id -un`, но не всегда. Запись с отдельным значением (`tail -n 4`) и слова-условия (`find -name`) используйте в показанной форме.

### Перенаправление не является опцией команды

```bash
grep 'WARN' ../logs/practice.log
grep 'WARN' ../logs/practice.log > warnings.txt
```

Первая строка выводит результат на экран. Во второй `>` — знак оболочки, меняющий направление стандартного вывода на `warnings.txt`, а не опция `grep`. Проверьте сохранение через `cat warnings.txt`. `>>` добавляет текст в конец файла.

## Читайте find поэтапно

`tree` помогает видеть форму всего дерева. `find` позволяет ограничить результаты условиями. В P1 сначала осматривают структуру через `tree`, затем находят файлы `.tmp` через `find` и только после проверки удаляют конкретные пути через `rm`.

### Отделите начальный каталог, условия и вывод

```bash
find . -type f -name '*.tmp' -print
```

Читайте: «Обойти текущий каталог и его потомков; показать пути обычных файлов, имя которых заканчивается на `.tmp`».

| Часть | Значение | Подсказка |
| --- | --- | --- |
| `find` | Команда поиска. | find — найти. |
| `.` | Начальное место. | Текущий каталог и его потомки. |
| `-type f` | Условие: обычный файл. | type — тип; каталог — `-type d`. |
| `-name '*.tmp'` | Условие: имя совпадает с шаблоном. | Содержимое файла не ищется. |
| `-print` | Действие: вывести путь. | Не означает печать на бумаге. |

`-type` и `-name` — тесты (условия), `-print` — действие. Условия без явного оператора между ними обычно связываются логическим И: каталог с именем `something.tmp` не попадёт в результат при `-type f`. Простой поиск обычно выводит пути и без `-print`; здесь действие указано для ясности.

### Добавляйте условия постепенно

В P1 запускайте строки по одной и сравнивайте:

```bash
cd ~/jdu-lab/p1/practice01
find . -print
find . -type f -print
find . -type f -name '*.tmp' -print
```

Сначала видны начальная точка и все элементы, затем только файлы, наконец только файлы с окончанием `.tmp`. До удаления результат содержит два пути (порядок может быть иным):

```text
./staging/training.conf.tmp
./staging/practice.log.tmp
```

Если файлы уже удалены в шаге 6, отсутствие вывода нормально. Не сбрасывайте задание только ради этого примера.

### Зачем нужны кавычки

`*` в `'*.tmp'` означает произвольную последовательность символов, включая пустую. Кавычки не дают оболочке раскрыть шаблон по именам текущего каталога; `find` получит его без изменений и проверит имена на каждом уровне. Без кавычек аргумент может измениться ещё до запуска `find`.

`-name` проверяет только имя объекта, без родительских каталогов. Для шаблона всего пути есть `-path`. Это шаблоны имён, а не регулярные выражения.

### Другие условия по мере необходимости

| Указание | Английская подсказка | Значение |
| --- | --- | --- |
| `-type d` | directory | Только каталоги. |
| `-iname '*.log'` | case-insensitive name | Имя без учёта регистра. |
| `-path './staging/*'` | path | Шаблон полного пути. |
| `-maxdepth 2` | maximum depth | Обход до глубины 2, начальная точка — глубина 0. |
| `-mindepth 1` | minimum depth | Не включать начальную точку. |
| `-empty` | empty | Пустой файл или пустой каталог. |
| `-user ssm-user` | user | Объект указанного владельца. |

Ограничения глубины удобно ставить сразу после начального пути. Пример: обычные файлы не глубже двух уровней.

```bash
find . -maxdepth 2 -type f -print
```

### Отделяйте поиск от удаления

В P1 `find` только показывает результаты. После проверки удаляйте точные пути через `rm`:

```bash
rm staging/training.conf.tmp staging/practice.log.tmp
tree
find . -type f -name '*.tmp' -print
```

Сверьте структуру через `tree`, затем убедитесь, что `find` больше не показывает `.tmp`. У `find` есть действия `-delete` и `-exec`, которые изменяют объекты или запускают команды; пока не научились читать результат, разделяйте поиск и удаление.

## Ищите строки внутри файла через grep

`grep` выводит строки, совпавшие с шаблоном. Название происходит от записи `g/re/p` (global / regular expression / print) редактора Unix `ed`. Запомните: `find` ищет объекты по имени или типу, `grep` — строки внутри файла.

```bash
grep 'WARN' ../logs/practice.log
```

Здесь `grep` — команда, `'WARN'` — шаблон, а `../logs/practice.log` — файл. По умолчанию регистр учитывается, шаблон трактуется как базовое регулярное выражение. `WARN` находит строку с этими буквами. Выводится вся строка, а не только слово.

| Опция | Длинная форма | Значение |
| --- | --- | --- |
| `-n` | `--line-number` | Добавляет исходный номер строки. |
| `-i` | `--ignore-case` | Игнорирует регистр. |
| `-F` | `--fixed-strings` | Буквальная строка вместо регулярного выражения. |
| `-v` | `--invert-match` | Показывает не совпавшие строки. |
| `-c` | `--count` | Число совпавших строк, не число вхождений слова. |

Например, `grep -n 'WARN' ../logs/practice.log` добавляет номера. Если файл для P1/M1 должен содержать исходные строки без номеров, не используйте `-n` при сохранении. `grep -F` ищет буквальную строку.

### Сначала посмотрите, затем сохраните

```bash
grep 'WARN' ../logs/practice.log
grep 'WARN' ../logs/practice.log > warnings.txt
cat warnings.txt
```

Сначала посмотрите найденные строки, затем запишите тот же результат и перечитайте файл. При перенаправлении `>` отсутствие вывода на экране нормально. Если строк нет, это может означать отсутствие совпадений. Обычные коды завершения `grep`: 0 — совпадение, 1 — нет совпадения, 2 — ошибка. Отличайте отсутствие совпадения от ошибки чтения файла.

## Читайте конец файла через tail

`tail` означает «хвост». Без опций `tail FILE` показывает последние десять строк (или все, если их меньше). Это удобно для последних событий журнала.

```bash
tail -n 4 ../logs/practice.log
```

`-n 4` задаёт число строк, а `../logs/practice.log` — читаемый файл. `-n` здесь соответствует `--lines`, а не добавлению номеров, как у `grep -n`.

| Опция | Длинная форма | Значение |
| --- | --- | --- |
| `-n 4` | `--lines=4` | Последние четыре строки. |
| `-n 5` | `--lines=5` | Последние пять строк. |
| `-f` | `--follow` | Продолжать показывать добавленные строки. |

`tail` не переворачивает строки. Он выбирает последние строки, сохраняя порядок файла: четыре в P1, пять в M1.

### Сначала посмотрите, затем сохраните

```bash
tail -n 4 ../logs/practice.log
tail -n 4 ../logs/practice.log > recent.txt
cat recent.txt
```

Первая строка помогает проверить число и порядок, вторая сохраняет вывод. `recent.txt` должен совпасть с последними четырьмя строками. `tail -f FILE` продолжает ждать новых записей; выйдите из него через Ctrl+C. Для создания файла задания используйте завершающуюся команду `tail -n N FILE`.

## Как выяснять неизвестные опции

```bash
id --help
find --help
man find
help cd
```

`--help` даёт краткую справку многих внешних команд, `man` — подробное руководство, `help` — справку встроенных команд Bash. Из `man` выходят клавишей `q`. Если `man` не установлен в Lab, используйте `--help`, `help` или официальные материалы:

- [GNU Coreutils: id](https://www.gnu.org/software/coreutils/manual/html_node/id-invocation.html)
- [GNU Grep](https://www.gnu.org/software/grep/manual/grep.html)
- [GNU Coreutils: tail](https://www.gnu.org/software/coreutils/manual/html_node/tail-invocation.html)
- [GNU Findutils](https://www.gnu.org/software/findutils/manual/html_mono/find.html)

Проверяйте по порядку: (1) назначение команды, (2) смысл опции, (3) значение после неё, (4) объект действия. Обращаясь к ИИ, просите разобрать `find . -type f -name '*.tmp' -print` по частям и сверяйте ответ со справкой.
