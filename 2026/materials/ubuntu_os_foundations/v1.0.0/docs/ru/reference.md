# Основы Ubuntu и ОС: термины и краткий справочник команд

[日本語](../ja/reference.md) · [Русский](../ru/reference.md) · [O‘zbekcha](../uz/reference.md)

Среда: Ubuntu Server 24.04 LTS / открытый Lab v1.0.0. Это не таблица для заучивания. Найдите команду по задаче, затем при необходимости перечитайте в учебнике параметры и способ проверки.

## Термины

| Русский термин | English | Значение |
| --- | --- | --- |
| ОС | operating system | Базовая система, управляющая оборудованием и предоставляющая функции процессов, файлов, контроля доступа и связи. |
| ядро | kernel | Центральная работающая часть ОС; управляет процессором, памятью, устройствами, процессами, файлами и сетью. |
| пространство пользователя | user space | Область работы обычных программ, включая оболочку, команды и службы, отделённая от ядра. |
| дистрибутив | distribution | Набор ядра Linux, инструментов, пакетов, настроек и правил обновления; Ubuntu — пример. |
| интерфейс командной строки | command-line interface (CLI) | Способ обмена текстовыми командами и результатами. |
| терминал | terminal | Экран или интерактивное соединение для ввода и вывода текста. |
| командная оболочка | shell | Программа, разбирающая текст и выполняющая команды; в практике обычно Bash. |
| файл | file | Базовый объект хранения содержимого и метаданных. |
| каталог | directory | Особый файл, связывающий имена объектов и образующий иерархию. |
| путь | path | Строка, указывающая объект через последовательность каталогов. |
| владелец | owner | Пользователь, записанный владельцем в метаданных файла или каталога. |
| основная группа | primary group | Одна базовая группа, назначенная пользователю. |
| дополнительная группа | supplementary group | Группа, в которой пользователь состоит дополнительно, например для общего ресурса. |
| права доступа | permission | Разрешения чтения (r), записи (w), выполнения (x) для владельца (u), группы (g), остальных (o). |
| программа | program | Сохранённые на накопителе исполняемые инструкции и связанные файлы. |
| процесс | process | Работающий в памяти экземпляр программы со своим PID и учётными данными. |
| пакет | package | Набор файлов, версии, зависимостей и действий для распространения и установки ПО. |
| служба | service | Управляемая системой длительная фоновая функция и её единица управления. |
| юнит | unit | Конфигурационная единица, через которую systemd управляет службой или другим ресурсом. |
| сокет | socket | Интерфейс процесса к сетевым функциям ядра. |
| ожидание соединений | listen | Состояние сокета, готового принимать соединения клиентов. |
| обратная петля | loopback | Виртуальный сетевой интерфейс для обмена внутри одного хоста; пример IPv4 — `127.0.0.1`. |
| порт | port | Число для различения точек сетевого обмена внутри хоста. |
| журнал | log | Записи истории работы, ошибок и изменения состояния программы или ОС. |
| локальный | local | Среда, из которой начинается SSH-соединение или перенос SCP; здесь AWS CloudShell. |
| удалённый | remote | Сервер назначения SSH/SCP; здесь Ubuntu EC2. |
| аутентификация | authentication | Проверка, действительно ли субъект тот, за кого себя выдаёт. |
| проверка прав доступа | authorization | Решение, разрешена ли аутентифицированному субъекту конкретная операция. |

## Основные команды

| Задача | Команда и параметры | Риск или частая ошибка | Проверка результата |
| --- | --- | --- | --- |
| Текущий каталог | `pwd` | Не судите только по строке приглашения. | Сопоставьте путь с хостом и пользователем. |
| Переход | `cd PATH`, `cd ..`, `cd ~` | Относительный путь зависит от текущего каталога. | `pwd`. |
| Список | `ls -la`, `ls -ld DIR` | `-l DIR` показывает содержимое, `-ld DIR` — сам каталог. | При необходимости `stat`, `tree`. |
| Дерево каталогов | `tree PATH` | Не показывает всё содержимое файлов и все подробности прав. | Сопоставьте с `ls -l`. |
| Создание каталога | `mkdir -p PATH` | Не создайте ошибочное дерево из-за неверного пути. | `tree`, `ls -ld`. |
| Копирование | `cp SOURCE DEST` | Не перепутайте источник и назначение; берегитесь перезаписи. | `cat`, `sha256sum`. |
| Перемещение или переименование | `mv SOURCE DEST` | Возможна непреднамеренная перезапись. | `ls`. |
| Удаление | `rm FILE` | Обычно нет «корзины»; в заданиях не используйте `rm -rf`. | Перед удалением `pwd`, `ls`; после него убедитесь в отсутствии. |
| Редактирование | `nano FILE` | Проверьте путь и сохранение. | `Ctrl+O`, `Enter`, `Ctrl+X`, затем `cat`. |
| Чтение | `cat FILE`, `less FILE` | Не выводите через `cat` огромный или двоичный файл. | Выйдите из `less` клавишей `q`. |
| Поиск строк | `grep [-F] PATTERN FILE` | `-n` добавляет номер строки; не включайте его, если нужна исходная строка. | Сверьте строки и код завершения. |
| Последние строки | `tail -n N FILE` | Здесь `-n` означает число строк, не то же, что у `grep`. | Проверьте число и порядок. |
| Запись stdout | `>`, `>>` | `>` обнуляет существующий файл; не указывайте входной файл и выходной как один и тот же. | `cat`, `wc -l`. |
| Конвейер | `\|` | Через него проходит stdout, но обычно не stderr. | Сначала проверьте каждую команду отдельно. |
| Пользователь и группы | `id [USER]`, `groups [USER]` | Различайте запись об аккаунте и группы работающего сеанса. | После нового входа выполните `id`. |
| База учётных записей | `getent passwd USER`, `getent group GROUP` | Список членов группы может не показывать тех, для кого она основная. | Сопоставьте с `id USER`. |
| Переключение пользователя | `sudo su - USER`, `exit` | Оболочки вкладываются друг в друга; учебные пользователи не имеют sudo. | После каждого перехода `id -un`, `pwd`. |
| Одна команда под другим пользователем | `sudo -u USER -- COMMAND` | Успех под root не доказывает успех под нужным пользователем. | Сразу проверьте `echo $?`. |
| Добавить в группу | `usermod -aG GROUP USER` | Без `-a` параметр `-G` может удалить другие дополнительные группы. | `id USER` и новый сеанс. |
| Удалить из группы | `gpasswd -d USER GROUP` | Соблюдайте порядок имени пользователя и группы. | `id USER`. |
| Сменить владельца и группу | `chown OWNER:GROUP PATH` | Рекурсивный `-R` может затронуть лишние файлы. | `stat -c '%U:%G %a %n'`. |
| Сменить режим | `chmod MODE PATH` | Не ставьте `777` без причины; `x` у файла и каталога различается. | `stat` и `test` под другим пользователем. |
| Процессы | `ps -e -o ...`, `ps -p PID -o ...` | Не копируйте пример PID из учебника. | Сверьте пользователя, команду и PID. |
| Сигнал процессу | `kill -TERM PID` | Убедитесь, что PID не пуст, не 0, не отрицателен и не 1. `pkill` не принимает PID в этом смысле. | `ps` или состояние службы. |
| Пакеты | `apt show NAME`, `sudo apt update`, `sudo apt install NAME` | Различайте индекс (`update`) и обновление пакетов (`upgrade`); читайте перечень изменений. | `command -v`, `dpkg-query`. |
| Настройка службы | `systemctl cat UNIT` | Не редактируйте учебный юнит без задания. | Сверьте `User`, `WorkingDirectory`, `ExecStart`. |
| Состояние службы | `systemctl status/start/stop` | `active` не гарантирует исправность функции. | `is-active`, MainPID, `curl`. |
| Автозапуск | `systemctl enable/disable UNIT` | `start/stop` и `enable/disable` — разные действия. | `is-enabled`. |
| Главный PID | `systemctl show -p MainPID --value UNIT` | Значение может быть 0, пустым или устареть после перезапуска. | `ps -p PID`. |
| Сокеты | `sudo ss -lntp` | Сверьте адрес, порт и PID. | Сопоставьте с Main PID. |
| HTTP | `curl -i URL`, при необходимости `--max-time` | Успешное TCP-соединение, статус HTTP и тело ответа — отдельные проверки. | Строка статуса, тело, код завершения. |
| Системный журнал | `sudo journalctl -u UNIT --no-pager -n N` | Не смешивайте старый запуск с текущим. | Найдите нужный путь запроса. |
| SSH | `ssh HOST`, `ssh HOST 'COMMAND'` | Отличайте псевдоним SSH от DNS-имени, локальную подстановку от удалённой; берегите ключ. | На адресате: `id -un`, `hostname`, `pwd`. |
| Передача SCP | `scp SOURCE DEST` | Не перепутайте направление и не перезапишите файл. | Сравните `sha256sum` на обеих сторонах и `stat` на адресате. |

## Используются на занятиях, но не требуют запоминания

`uname -r`, `hostname`, `find`, `touch`, `stat`, `namei -l`, `test -r/-w`, `echo $?`, `printf`, `command -v`, `dpkg-query`, `dpkg -S`, `sha256sum`, `readlink`, `tr`, `/proc/PID/`.

При необходимости возвращайтесь к назначению и чтению вывода в учебнике, к `man`/`help` и этой таблице.

## Команды последующих разделов курса

`ip`, `ping`, `dig`, `tcpdump`, `mount`, `df`, `psql`. Здесь показана связь с темой; подробная настройка изучается в разделах сети, хранилищ, DNS и баз данных.

## Вне рамок этой книги

Сборка и отладка ядра, внутреннее выполнение инструкций CPU, алгоритмы замещения страниц памяти, планировщик дискового ввода-вывода, создание файловых систем и изменение разделов диска, сканирование портов внешних хостов, изменение настроек SSH-сервера.
