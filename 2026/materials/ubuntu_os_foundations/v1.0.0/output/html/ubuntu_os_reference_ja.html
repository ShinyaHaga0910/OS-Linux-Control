コマンドの読み方

コマンドは「名前・オプション・対象」に分けると読みやすい。例えば、tail -n 4 practice.logでは、tailが実行するプログラム、-n 4が行数を指定するオプションと値、practice.logが読む対象である。空白で区切られた部分を順に読む。マニュアルに出るFILEやPATH、Nなどの大文字は、実際のファイル名・パス・数値に置き換える説明用の記号である。

オプションは動作を変える指定である。短い形式は-uのように1文字、長い形式は--userのように単語で表すことが多い。ただし、すべてのコマンドが両方に対応するわけではない。findの-nameのように、ハイフンが1つでも単語を使う指定もある。綴りから推測した後、必ずそのコマンドの説明で意味を確認する。

id -unを分解して読む

idはユーザーやグループの識別情報を表示する。オプションなしのidはUID、GID、所属グループなどをまとめて表示する。

id
id -u
id -u -n
id -un

-uは--userに対応し、現在の実効ユーザーIDだけを表示する。-nは--nameに対応し、番号の代わりに名前を表示する。したがってid -u -nとid -unは同じ意味で、今回のUbuntu接続直後ならssm-userを表示する。

id -nだけでは、どのIDを名前に変えるか決まらない。 -nは-u、-g、-Gのいずれかと組み合わせる。id -gnは実効グループ名、id -Gnは所属する全グループの名前を表示する。英語を手掛かりにするだけでなく、組み合わせの条件まで確認する。

同じ文字でも、コマンドによって意味が変わる

実行例オプションの英語・意味実行結果
id -un-u＝user、-n＝name現在の実効ユーザー名
grep -n 'WARN' practice.log-n＝--line-number一致した行に行番号を付ける
tail -n 4 practice.log-n＝--lines。続く4が行数最後の4行を表示する
ls -la-l＝long形式、-a＝all詳細表示で、隠しファイルも含める
mkdir -p logs/archive-p＝--parents必要な親ディレクトリも作る
grep -F 'WARN' practice.log-F＝--fixed-strings正規表現ではなく文字列として検索する
chown -R USER DIR-R＝--recursiveDIRの中まで再帰的に所有者を変更する

id -unのようにまとめられる短いオプションもあるが、すべてをまとめられるとは限らない。tail -n 4のように値を取る指定や、find -nameのような単語の指定は、今回の例の形で入力する。

保存記号はコマンドのオプションではない

1行目は結果を画面に表示する。2行目の>は、シェルが標準出力の行き先をwarnings.txtへ変える記号であり、grepのオプションではない。保存できたらcat warnings.txtで内容を確認する。>>は追記する記号である。

findを段階的に読む

treeはディレクトリ全体の形を見て探すのに向いている。findは条件を指定して対象を絞り込むのに向いている。P1では、まずtreeで構成を観察し、次にfindで.tmpファイルを検索し、確認したパスをrmへ指定する。

検索開始位置・条件・表示に分ける

find . -type f -name '*.tmp' -print

このcommandは「現在地以下をたどり、通常のファイルで、名前が.tmpで終わるもののパスを表示する」と読む。

部分意味覚え方・注意
find検索するコマンドfind＝探す
.検索を始める位置現在のディレクトリ。配下もたどる
-type f通常のファイルに限定する条件type＝種類、f＝file。ディレクトリなら-type d
-name '*.tmp'名前がパターンに一致する条件name＝名前。ファイル内容は検索しない
-print一致したパスを表示する動作print＝出力する。ファイルを印刷する意味ではない

-typeと-nameは正確には「テスト（条件）」、-printは「アクション（動作）」である。間に演算子を置かない複数の条件は、通常「両方を満たす」というANDとして評価される。今回の-type f -name '*.tmp'なら、名前が一致してもディレクトリは表示しない。

-printなどの動作を省いた単純な検索では、通常、検索結果のパスが表示される。ここでは何をするか読み取れるように-printを明示する。

小さい指定から条件を足す

P1で、次を1行ずつ実行して表示の変化を比べる。

cd ~/jdu-lab/p1/practice01
find . -print
find . -type f -print
find . -type f -name '*.tmp' -print

最初は開始位置自身と配下の項目を表示し、次は通常のファイルだけを表示し、最後は名前が.tmpで終わる通常のファイルだけを表示する。1段階ずつ条件を足すと、各指定が何を絞っているか理解しやすい。

削除前のP1では、最後の検索で次の2つが表示される。表示順は保証されない。

./staging/training.conf.tmp
./staging/practice.log.tmp

すでに手順6で削除した場合は、この検索で何も表示されない。その場合も正常であり、確認のためだけに課題をリセットする必要はない。

なぜ引用符で囲むのか

'*.tmp'の*は、0文字以上の任意の文字列に一致する。このパターンを引用符で囲むと、シェルが現在地の名前に展開せず、findへそのまま渡す。findが各階層のファイル名に対して一致を調べる。引用符を外すと、現在地に同じパターンの名前がある場合、findを実行する前に引数が変わってしまう。

-nameは途中のディレクトリを含まない名前に対して調べる。training.conf.tmpを探すなら-name '*.tmp'を使う。パス全体に条件を付けたい場合は-pathを使う。これは正規表現ではなく、ファイル名パターンの検索である。

よく使う条件を必要なときに追加する

指定英語の手掛かり意味
-type ddirectoryディレクトリだけを検索する
-iname '*.log'大文字・小文字を区別しないname条件名前の大文字・小文字を区別せず検索する
-path './staging/*'pathパス全体がパターンに一致するものを検索する
-maxdepth 2maximum depth開始位置を深さ0として、深さ2までたどる
-mindepth 1minimum depth開始位置自身を結果に含めず、深さ1以降を評価する

-maxdepthや-mindepthは、検索の範囲を制御する指定なので、開始位置の直後に置くと読みやすい。例えば、次は現在地から2階層までで通常のファイルを探す。

find . -maxdepth 2 -type f -print

treeで構成を見直し、最後のfindで該当するパスが表示されないことを確認する。findには-deleteや-execのように対象を変更したり別のコマンドを実行したりする動作もあるが、今回の練習では使わない。例を読み取れるまでは、検索条件と結果の確認を分けて進める。

grepでファイルの中の行を探す

grepは、指定したパターンに一致する行を取り出す。名前はUnixの行エディターedのg/re/p（global / regular expression / print）に由来する。まずは「内容を検索し、一致する行を表示する」と覚える。findはファイル名や種類などを探し、grepはファイルの内容を探す。

grep 'WARN' ../logs/practice.log

grepがコマンド、'WARN'が探すパターン、../logs/practice.logが読むファイルである。既定では大文字・小文字を区別し、パターンを基本正規表現として解釈する。今回のWARNは、その文字列を含む行に一致する。表示されるのは一致した単語だけでなく、行全体である。

指定対応する英語・長い形式意味
-n--line-number一致した行に元の行番号を付ける
-i--ignore-case大文字・小文字を区別しない
-F--fixed-stringsパターンを正規表現ではなく文字列として扱う
-v--invert-match一致しない行を取り出す
-c--count一致した行の数を表示する。単語の出現回数ではない

例えば、grep -n 'WARN' ../logs/practice.logはWARN行に行番号を付ける。P1やM1で「行番号を付けない」と指定された提出ファイルでは、保存時に-nを使わない。grep -F 'WARN' ../logs/practice.logなら、検索する内容を通常の文字列として指定できる。

観察してから保存する

grep 'WARN' ../logs/practice.log
grep 'WARN' ../logs/practice.log > warnings.txt
cat warnings.txt

まず抽出する行が正しいか画面で確認し、その後、同じ検索の結果を別ファイルへ保存する。catで保存した内容を読み直す。>を付けた実行で画面に結果が表示されなくても、保存先へ出力されていれば正常である。

何も表示されない場合は、一致する行がないこともある。grepの終了ステータスは、通常、0が一致あり、1が一致なし、2がエラーである。ファイルが存在しない場合のエラー表示と、「一致する行がない」状態を区別する。

tailで末尾の行を読む

tailは英語で「末尾・しっぽ」を意味する。ログの最後にどのような出来事が記録されたか確認するときに使う。オプションを付けないtail FILEは、既定で最後の10行を表示する。行数がそれより少なければ、存在する行だけを表示する。

tail -n 4 ../logs/practice.log

tailがコマンド、-n 4が表示する行数、../logs/practice.logが読む対象である。-nは長い形式--linesに対応し、次の4を行数として受け取る。grep -nの「行番号を付ける」とは意味が異なる。

指定対応する英語・長い形式意味
-n 4--lines=4最後の4行を表示する
-n 5--lines=5最後の5行を表示する
-f--follow終了せず、新しく追加された内容も表示する

tailは最後の行から逆順に表示するコマンドではない。選ばれた末尾の行を、ファイル内と同じ順序で表示する。P1では最後の4行、M1では最後の5行を指定する。

観察してから保存する

tail -n 4 ../logs/practice.log
tail -n 4 ../logs/practice.log > recent.txt
cat recent.txt

最初の実行で行数と順序を観察し、次の実行で保存する。P1ではrecent.txtの内容が最後の4行と一致することを確認する。

ログを見続ける補助的な操作にはtail -f FILEがある。これは入力を待つ状態になるため、終了するときはCtrl+Cを押す。提出ファイルを作る今回の手順では、終了するtail -n N FILEを使う。

意味がわからない指定を調べる

id --help
find --help
man find
help cd

--helpは多くの外部コマンドの短い説明、manは詳しいマニュアル、helpはBash内蔵コマンドの説明を読む手段である。manの画面はqで終了する。Labでmanや個別のマニュアルが未導入なら、--help、helpまたは次の公式資料を使う。

  • GNU Coreutils: id
  • GNU Grepマニュアル
  • GNU Coreutils: tail
  • GNU Findutilsマニュアル

調べる順序は、(1) コマンドの役割、(2) オプションの意味、(3) 続く値、(4) 操作する対象である。AIに相談する場合も、find . -type f -name '*.tmp' -printを各部分に分けて説明してもらい、--helpやマニュアルと照合する。
