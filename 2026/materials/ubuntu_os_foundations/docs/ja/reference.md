## 必須コマンド

| 目的 | コマンド・必要オプション | 注意すべき点・誤解 | 操作後の確認 |
| --- | --- | --- | --- |
| 現在位置 | `pwd` | プロンプトの表示文字列だけで判断せず、現在位置を確認する | 出力されたパスとホスト名・ユーザー名を照合する |
| 移動 | `cd PATH`、`cd ..`、`cd ~` | 相対パスはカレントディレクトリ（現在位置）に依存する | `pwd` |
| 一覧 | `ls -la`、`ls -ld DIR` | `-l DIR`はディレクトリ内の項目一覧を表示し、`-ld DIR`はディレクトリ自身の属性を表示する | 必要に応じて`stat`や`tree`を併用する |
| 階層表示 | `tree PATH` | 階層構造は把握できるが、ファイル内容やアクセス権までは網羅しない | `ls -l`等と併用する |
| ディレクトリ作成 | `mkdir -p PATH` | 意図しない階層パスを誤作成しない | `tree`、`ls -ld` |
| コピー | `cp SOURCE DEST` | コピー元とコピー先の順序間違い、意図しない上書きに注意する | `cat`、`sha256sum` |
| 移動・改名 | `mv SOURCE DEST` | 移動先への不用意な上書きに注意する | `ls` |
| 削除 | `rm FILE` | 通常のGUIのような「ごみ箱」はない。演習課題では安全のため`rm -rf`を使用しない | 実行前に`pwd`と`ls`で対象を確認し、実行後に不在を確認する |
| 編集 | `nano FILE` | 意図したファイル名・パスで保存したか、未保存のまま終了していないか確認する | Ctrl+O、Enterで保存し、Ctrl+Xで終了後、`cat`で内容を再確認する |
| 内容表示 | `cat FILE`、`less FILE` | バイナリファイルや極端に巨大なファイルを不用意に`cat`しない | `less`は`q`で終了する |
| 検索 | `grep [-F] PATTERN FILE` | `-n`は行番号を付加する。課題の提出要件に行番号が含まれていない場合は付けない | 出力された一致行と終了ステータスを確認する |
| 末尾 | `tail -n N FILE` | `-n`は出力行数を指定する（`grep -n`の行番号表示とは意味が異なる） | 行数と順序を確認する |
| 標準出力を保存 | `>`、`>>` | `>`は既存内容を切り詰めて（空にして）上書きする。入力元と同じファイルを指定すると内容を失う | `cat`、`wc -l` |
| コマンド接続 | `|` | 標準出力だけが渡され、標準エラー出力（stderr）はパイプを流れない | パイプで連結する前に、各コマンドを単独でも実行して動作を確認する |
| ユーザー/グループ | `id [USER]`、`groups [USER]` | アカウントの登録情報と、起動済みセッションが保持する資格情報を区別する | 新しいセッション（ログインシェル）を開始した上で`id`を実行する |
| アカウントDB | `getent passwd USER`、`getent group GROUP` | グループエントリの末尾一覧には、そのグループを主グループとしているユーザーが含まれない場合がある | `id USER`と併用して確認する |
| ユーザー切り替え | `sudo su - USER`、`exit` | シェルが多重に入れ子になる点に注意する。演習用一般ユーザーにはsudo権限がない | 切り替えのたびに`id -un`や`pwd`で現在状態を確認する |
| 1コマンドだけ別ユーザー | `sudo -u USER -- COMMAND` | rootでの実行成功を、対象ユーザーでも成功する証拠とみなさない | 実行直後に`echo $?`で終了ステータスを確認する |
| グループ追加 | `usermod -aG GROUP USER` | `-a`なしで`-G`を指定すると、記載しなかった既存の補助グループから除外される | `id USER`を実行し、新しいセッションで確認する |
| グループ削除 | `gpasswd -d USER GROUP` | ユーザー名とグループ名の指定順序に注意する | `id USER` |
| 所有者/グループ変更 | `chown OWNER:GROUP PATH` | 再帰的変更（`-R`）による影響範囲に注意する | `stat -c '%U:%G %a %n'` |
| モード変更 | `chmod MODE PATH` | 安易に`777`を設定しない。ファイルとディレクトリで実行権限（x）の意味が異なる | `stat`や別ユーザーでの`test`コマンドで確認する |
| プロセス一覧 | `ps -e -o ...`、`ps -p PID -o ...` | 教科書の例示PIDをそのまま入力しない | ユーザー名、コマンド名、PIDが一致していることを照合する |
| シグナル送信 | `kill -TERM PID` | PID変数が空、0、負値、1（PID 1）でないことを確認する。PIDに対して`pkill`を使わない | `ps`やサービスの稼働状態で終了を確認する |
| パッケージ情報・導入 | `apt show NAME`、`sudo apt update`、`sudo apt install NAME` | `apt update`（一覧更新）と`apt upgrade`（本体更新）の違いを理解する。演習環境で無関係な全体更新を行わない | `command -v`、`dpkg-query` |
| サービス設定 | `systemctl cat UNIT` | 演習用のユニットファイルを直接編集しない | `User`、`WorkingDirectory`、`ExecStart`の各項目を確認する |
| サービス状態 | `systemctl status/start/stop` | active（起動中）であることだけで、機能全体が正常に動作していると判断しない | `is-active`、MainPID、curlなどで多角的に確認する |
| 起動時自動起動 | `systemctl enable/disable UNIT` | 即時起動（`start`/`stop`）と自動起動設定（`enable`/`disable`）は別軸である | `is-enabled` |
| Main PID確認 | `systemctl status UNIT` | `Main PID:`に表示された番号を現在の値として読む。停止中は表示されない場合がある | `ps -fp PID` |
| ソケット状態 | `sudo ss -lntp` | アドレス、ポート番号、プロセスPIDをすべて照合する | サービスのMain PIDと比較する |
| HTTP疎通 | `curl -i URL`、必要時`--max-time` | TCP接続の成功、HTTPステータスコード、応答本文の内容はそれぞれ個別に確認する | ステータスライン、本文、終了ステータスを確認する |
| ジャーナルログ | `sudo journalctl -u UNIT --no-pager -n N` | 過去の古い起動ログと、現在の実行ログを混同しない | 指定されたリクエストパスが記録されているか確認する |
| SSH接続 | `ssh HOST`、`ssh HOST 'COMMAND'` | ホストエイリアスとDNSホスト名の違い、クォートによるローカル/リモートでの変数展開の違い、秘密鍵の保護に注意する | `id -un`、`hostname`、`pwd`で接続先環境を確認する |
| SCPファイル転送 | `scp SOURCE DEST` | 転送元（source）と転送先（destination）の取り違え、不用意な上書きに注意する | 両環境で`sha256sum`を比較し、リモート側で`stat`を確認する |

## コマンドの読み方

コマンドは「名前・オプション・対象」に分けると読みやすい。例えば、`tail -n 4 practice.log`では、`tail`が実行するプログラム、`-n 4`が行数を指定するオプションと値、`practice.log`が読む対象である。空白で区切られた部分を順に読む。マニュアルに出る`FILE`や`PATH`、`N`などの大文字は、実際のファイル名・パス・数値に置き換える説明用の記号である。

オプションは動作を変える指定である。短い形式は`-u`のように1文字、長い形式は`--user`のように単語で表すことが多い。ただし、すべてのコマンドが両方に対応するわけではない。`find`の`-name`のように、ハイフンが1つでも単語を使う指定もある。綴りから推測した後、必ずそのコマンドの説明で意味を確認する。

### 英語の意味と結び付けて覚える

次の英語は、コマンドを覚えるための手掛かりである。すべてを歴史的な正式名称・略語の由来として断定するものではない。`find`や`tail`は、英単語そのものを使っている。

| コマンド | 覚えるための英語 | 読み方・用途 |
| --- | --- | --- |
| `pwd` | print working directory | 現在作業しているディレクトリを表示する |
| `cd` | change directory | 作業するディレクトリを変える |
| `ls` | list | 名前の一覧を表示する |
| `mkdir` | make directory | ディレクトリを作る |
| `cp` | copy | コピーする。コピー元、コピー先の順に指定する |
| `mv` | move | 移動する。同じディレクトリ内なら名前変更にも使う |
| `rm` | remove | 指定したファイルを削除する |
| `cat` | concatenate（連結する） | 複数ファイルの内容を連結して表示する。1ファイルの表示にも使う |
| `tree` | tree（木） | 枝のような形でディレクトリ構成を表示する |
| `find` | find（探す） | ディレクトリをたどり、条件に合うファイルやディレクトリを探す |
| `grep` | global / regular expression / print（`g/re/p`に由来） | ファイルの中の行を検索する。ファイル名を探す`find`と区別する |
| `tail` | tail（末尾・しっぽ） | ファイルの末尾の行を表示する |
| `id` | identity / identifier（識別情報・識別子） | ユーザーやグループの識別情報を表示する |
| `chown` | change owner | 所有者を変更する |
| `chmod` | change mode | アクセス権のモードを変更する |
| `ssh` | Secure Shell | 別のコンピューターへ安全な通信で接続する |

### id -unを分解して読む

`id`はユーザーやグループの識別情報を表示する。オプションなしの`id`はUID、GID、所属グループなどをまとめて表示する。

```bash
id
id -u
id -u -n
id -un
```

`-u`は`--user`に対応し、現在の実効ユーザーIDだけを表示する。`-n`は`--name`に対応し、番号の代わりに名前を表示する。したがって`id -u -n`と`id -un`は同じ意味で、今回のUbuntu接続直後なら`ssm-user`を表示する。

**`id -n`だけでは、どのIDを名前に変えるか決まらない。** `-n`は`-u`、`-g`、`-G`のいずれかと組み合わせる。`id -gn`は実効グループ名、`id -Gn`は所属する全グループの名前を表示する。英語を手掛かりにするだけでなく、組み合わせの条件まで確認する。

### 同じ文字でも、コマンドによって意味が変わる

| 実行例 | オプションの英語・意味 | 実行結果 |
| --- | --- | --- |
| `id -un` | `-u`＝user、`-n`＝name | 現在の実効ユーザー名 |
| `grep -n 'WARN' practice.log` | `-n`＝`--line-number` | 一致した行に行番号を付ける |
| `tail -n 4 practice.log` | `-n`＝`--lines`。続く`4`が行数 | 最後の4行を表示する |
| `ls -la` | `-l`＝long形式、`-a`＝all | 詳細表示で、隠しファイルも含める |
| `mkdir -p logs/archive` | `-p`＝`--parents` | 必要な親ディレクトリも作る |
| `grep -F 'WARN' practice.log` | `-F`＝`--fixed-strings` | 正規表現ではなく文字列として検索する |
| `chown -R USER DIR` | `-R`＝`--recursive` | DIRの中まで再帰的に所有者を変更する |

`id -un`のようにまとめられる短いオプションもあるが、すべてをまとめられるとは限らない。`tail -n 4`のように値を取る指定や、`find -name`のような単語の指定は、今回の例の形で入力する。

### 保存記号はコマンドのオプションではない

```bash
grep 'WARN' ../logs/practice.log
grep 'WARN' ../logs/practice.log > warnings.txt
```

1行目は結果を画面に表示する。2行目の`>`は、シェルが標準出力の行き先を`warnings.txt`へ変える記号であり、`grep`のオプションではない。保存できたら`cat warnings.txt`で内容を確認する。`>>`は追記する記号である。

## findを段階的に読む

`tree`はディレクトリ全体の形を見て探すのに向いている。`find`は条件を指定して対象を絞り込むのに向いている。P1では、まず`tree`で構成を観察し、次に`find`で`.tmp`ファイルを検索し、確認したパスを`rm`へ指定する。

### 検索開始位置・条件・表示に分ける

```bash
find . -type f -name '*.tmp' -print
```

このcommandは「現在地以下をたどり、通常のファイルで、名前が`.tmp`で終わるもののパスを表示する」と読む。

| 部分 | 意味 | 覚え方・注意 |
| --- | --- | --- |
| `find` | 検索するコマンド | find＝探す |
| `.` | 検索を始める位置 | 現在のディレクトリ。配下もたどる |
| `-type f` | 通常のファイルに限定する条件 | type＝種類、f＝file。ディレクトリなら`-type d` |
| `-name '*.tmp'` | 名前がパターンに一致する条件 | name＝名前。ファイル内容は検索しない |
| `-print` | 一致したパスを表示する動作 | print＝出力する。ファイルを印刷する意味ではない |

`-type`と`-name`は正確には「テスト（条件）」、`-print`は「アクション（動作）」である。間に演算子を置かない複数の条件は、通常「両方を満たす」というANDとして評価される。今回の`-type f -name '*.tmp'`なら、名前が一致してもディレクトリは表示しない。

`-print`などの動作を省いた単純な検索では、通常、検索結果のパスが表示される。ここでは何をするか読み取れるように`-print`を明示する。

### 小さい指定から条件を足す

P1で、次を1行ずつ実行して表示の変化を比べる。

```bash
cd ~/jdu-lab/p1/practice01
find . -print
find . -type f -print
find . -type f -name '*.tmp' -print
```

最初は開始位置自身と配下の項目を表示し、次は通常のファイルだけを表示し、最後は名前が`.tmp`で終わる通常のファイルだけを表示する。1段階ずつ条件を足すと、各指定が何を絞っているか理解しやすい。

削除前のP1では、最後の検索で次の2つが表示される。表示順は保証されない。

```text
./staging/training.conf.tmp
./staging/practice.log.tmp
```

すでに手順6で削除した場合は、この検索で何も表示されない。その場合も正常であり、確認のためだけに課題をリセットする必要はない。

### なぜ引用符で囲むのか

`'*.tmp'`の`*`は、0文字以上の任意の文字列に一致する。このパターンを引用符で囲むと、シェルが現在地の名前に展開せず、`find`へそのまま渡す。`find`が各階層のファイル名に対して一致を調べる。引用符を外すと、現在地に同じパターンの名前がある場合、`find`を実行する前に引数が変わってしまう。

`-name`は途中のディレクトリを含まない名前に対して調べる。`training.conf.tmp`を探すなら`-name '*.tmp'`を使う。パス全体に条件を付けたい場合は`-path`を使う。これは正規表現ではなく、ファイル名パターンの検索である。

### よく使う条件を必要なときに追加する

| 指定 | 英語の手掛かり | 意味 |
| --- | --- | --- |
| `-type d` | directory | ディレクトリだけを検索する |
| `-iname '*.log'` | 大文字・小文字を区別しないname条件 | 名前の大文字・小文字を区別せず検索する |
| `-path './staging/*'` | path | パス全体がパターンに一致するものを検索する |
| `-maxdepth 2` | maximum depth | 開始位置を深さ0として、深さ2までたどる |
| `-mindepth 1` | minimum depth | 開始位置自身を結果に含めず、深さ1以降を評価する |
| `-empty` | empty＝空 | 空の通常ファイル、または空のディレクトリに一致する |
| `-user ssm-user` | user | 指定したユーザーが所有する項目に一致する |

`-maxdepth`や`-mindepth`は、検索の範囲を制御する指定なので、開始位置の直後に置くと読みやすい。例えば、次は現在地から2階層までで通常のファイルを探す。

```bash
find . -maxdepth 2 -type f -print
```

### 条件と削除を分ける

P1では`find`は検索と表示だけに使う。検索結果を確認してから、`rm`に具体的なパスを指定する。

```bash
rm staging/training.conf.tmp staging/practice.log.tmp
tree
find . -type f -name '*.tmp' -print
```

`tree`で構成を見直し、最後の`find`で該当するパスが表示されないことを確認する。`find`には`-delete`や`-exec`のように対象を変更したり別のコマンドを実行したりする動作もあるが、今回の練習では使わない。例を読み取れるまでは、検索条件と結果の確認を分けて進める。

## grepでファイルの中の行を探す

`grep`は、指定したパターンに一致する行を取り出す。名前はUnixの行エディター`ed`の`g/re/p`（global / regular expression / print）に由来する。まずは「内容を検索し、一致する行を表示する」と覚える。`find`はファイル名や種類などを探し、`grep`はファイルの内容を探す。

```bash
grep 'WARN' ../logs/practice.log
```

`grep`がコマンド、`'WARN'`が探すパターン、`../logs/practice.log`が読むファイルである。既定では大文字・小文字を区別し、パターンを基本正規表現として解釈する。今回の`WARN`は、その文字列を含む行に一致する。表示されるのは一致した単語だけでなく、行全体である。

| 指定 | 対応する英語・長い形式 | 意味 |
| --- | --- | --- |
| `-n` | `--line-number` | 一致した行に元の行番号を付ける |
| `-i` | `--ignore-case` | 大文字・小文字を区別しない |
| `-F` | `--fixed-strings` | パターンを正規表現ではなく文字列として扱う |
| `-v` | `--invert-match` | 一致しない行を取り出す |
| `-c` | `--count` | 一致した行の数を表示する。単語の出現回数ではない |

例えば、`grep -n 'WARN' ../logs/practice.log`はWARN行に行番号を付ける。P1やM1で「行番号を付けない」と指定された提出ファイルでは、保存時に`-n`を使わない。`grep -F 'WARN' ../logs/practice.log`なら、検索する内容を通常の文字列として指定できる。

### 観察してから保存する

```bash
grep 'WARN' ../logs/practice.log
grep 'WARN' ../logs/practice.log > warnings.txt
cat warnings.txt
```

まず抽出する行が正しいか画面で確認し、その後、同じ検索の結果を別ファイルへ保存する。`cat`で保存した内容を読み直す。`>`を付けた実行で画面に結果が表示されなくても、保存先へ出力されていれば正常である。

何も表示されない場合は、一致する行がないこともある。`grep`の終了ステータスは、通常、0が一致あり、1が一致なし、2がエラーである。ファイルが存在しない場合のエラー表示と、「一致する行がない」状態を区別する。

## tailで末尾の行を読む

`tail`は英語で「末尾・しっぽ」を意味する。ログの最後にどのような出来事が記録されたか確認するときに使う。オプションを付けない`tail FILE`は、既定で最後の10行を表示する。行数がそれより少なければ、存在する行だけを表示する。

```bash
tail -n 4 ../logs/practice.log
```

`tail`がコマンド、`-n 4`が表示する行数、`../logs/practice.log`が読む対象である。`-n`は長い形式`--lines`に対応し、次の`4`を行数として受け取る。`grep -n`の「行番号を付ける」とは意味が異なる。

| 指定 | 対応する英語・長い形式 | 意味 |
| --- | --- | --- |
| `-n 4` | `--lines=4` | 最後の4行を表示する |
| `-n 5` | `--lines=5` | 最後の5行を表示する |
| `-f` | `--follow` | 終了せず、新しく追加された内容も表示する |

`tail`は最後の行から逆順に表示するコマンドではない。選ばれた末尾の行を、ファイル内と同じ順序で表示する。P1では最後の4行、M1では最後の5行を指定する。

### 観察してから保存する

```bash
tail -n 4 ../logs/practice.log
tail -n 4 ../logs/practice.log > recent.txt
cat recent.txt
```

最初の実行で行数と順序を観察し、次の実行で保存する。P1では`recent.txt`の内容が最後の4行と一致することを確認する。

ログを見続ける補助的な操作には`tail -f FILE`がある。これは入力を待つ状態になるため、終了するときはCtrl+Cを押す。提出ファイルを作る今回の手順では、終了する`tail -n N FILE`を使う。

## 意味がわからない指定を調べる

```bash
id --help
find --help
man find
help cd
```

`--help`は多くの外部コマンドの短い説明、`man`は詳しいマニュアル、`help`はBash内蔵コマンドの説明を読む手段である。`man`の画面は`q`で終了する。Labで`man`や個別のマニュアルが未導入なら、`--help`、`help`または次の公式資料を使う。

- [GNU Coreutils: id](https://www.gnu.org/software/coreutils/manual/html_node/id-invocation.html)
- [GNU Grepマニュアル](https://www.gnu.org/software/grep/manual/grep.html)
- [GNU Coreutils: tail](https://www.gnu.org/software/coreutils/manual/html_node/tail-invocation.html)
- [GNU Findutilsマニュアル](https://www.gnu.org/software/findutils/manual/html_mono/find.html)

調べる順序は、(1) コマンドの役割、(2) オプションの意味、(3) 続く値、(4) 操作する対象である。AIに相談する場合も、`find . -type f -name '*.tmp' -print`を各部分に分けて説明してもらい、`--help`やマニュアルと照合する。
