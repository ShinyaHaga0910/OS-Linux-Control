# 日本語スタイルガイド（Ubuntu・OS基礎教材）

本書は、Linux未経験の大学生が基礎から無理なく理解できるよう、また多言語展開を進めやすくするために策定された日本語用字用語・文体ガイドラインである。現時点の翻訳元は日本語版であり、英語原本は未作成である。

---

## 1. 基本方針と文体

1. **「である」調（常体）の統一**
   - 本文はすべて「である」「だ」調（常体）で統一する。「です・ます」調（敬体）や不自然な体言止め（名詞止め）は原則として排除する。
   - 断定を避けるための過度な「～と思われる」「～かもしれない」の多用を避け、客観的な事実と理由を明瞭に述べる。

2. **対象読者への配慮**
   - 読者はIT/Linux未経験の大学生である。
   - 専門用語をいたずらに羅列せず、「なぜその仕組みが必要なのか」「裏で何が起きているのか」の因果関係が直感的に伝わる構文とする。

3. **翻訳容易性（Translatability）の確保**
   - 将来の英語・ウズベク語・ロシア語への翻訳を見据え、以下の点に配慮する：
     - **主語と述語の対応を明確にする**（省略された主語によって動作主体が曖昧になることを防ぐ）。
     - **文化依存の比喩や日本独自のスラングを避ける**。
     - **同一概念に対する表記揺れを徹底的に排除する**。
     - **一文を簡潔にし、修飾関係が複雑な重文・複文を避ける**。

## 2. 用語の採用基準と対訳ルール

## 3. 英語表記を維持する語（固有名詞・プロトコル・規格）

以下の語句は、IT分野の共通識別子・国際標準・固有名詞であるため、カタカナ化せず英大文字または原表記のまま維持する。

- **OS名・プロジェクト名**:
  `Linux`, `Ubuntu`, `Unix`, `Debian`, `Fedora`, `Windows`, `macOS`, `Darwin`, `BSD`, `GNU`
- **ソフトウェア・ツール名**:
  `systemd`, `systemctl`, `journald`, `journalctl`, `APT`, `Bash`, `nano`, `OpenSSH`
- **プロトコル・ネットワーク規格**:
  `SSH`, `SCP`, `HTTP`, `TCP`, `IP`, `IPv4`, `IPv6`, `UDP`, `DNS`
- **操作形態・識別子**:
  `GUI`, `CLI`, `PID`, `PPID`, `UID`, `GID`
- **AWS関連サービス・機能名**:
  `AWS CloudShell`, `Session Manager`, `EC2`, `IAM`, `ProxyCommand`
- **コマンド名・コード表記**:
  すべてのLinuxコマンド名（`ls`, `grep`, `cat`, `curl`, `ss`, `kill`, `chmod`, `chown`, `stat`, `namei` など）およびインラインコード内のオプション、パス名、環境変数名、Unit設定キー（`User=`, `ExecStart=` など）

## 4. 変更禁止対象と保全ルール

校閲および文体修正において、以下の要素を厳格に保全し、改変してはならない：

1. **インラインコードおよびコードブロック**
   - コマンド文字列、オプション引数、実行例、設定ファイルのコードブロックは一字一句変更しない。
2. **ファイルパス・識別子**
   - `/srv/jdu-share` などのパス名、`jdu-web.service` などのユニット名、`ssm-user` などのユーザー名・グループ名、チェックID（`M0`〜`M7`, `P1`〜`P6` など）は完全に維持する。
3. **リンクおよび画像参照パス**
   - 相対リンク（`../../../assets/figures/...` や `[参考資料](https://...)`）は変更しない。
4. **章節の構成・順序・技術的事実**
   - 見出しのレベル（`#`, `##`, `###`）や説明の順序、節立ては変更しない。
   - 要約や勝手な削除を行わず、説明の明確化に必要な最小限の語句補正にとどめる。
