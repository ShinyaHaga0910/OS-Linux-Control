# 多言語化の管理

## 原本

現時点の翻訳元は、内容を査読した`docs/ja/`である。`docs/en/`は未作成であり、将来の英語原本候補として扱う。英語版が完成した場合は、章単位で日本語・ウズベク語版との差分を再照合する。

## 対象言語

- `en`: 将来の英語原本候補（未作成）
- `ja`: 現在の翻訳元
- `uz`: ウズベク語（ChatGPT訳の初稿完成。母語話者による校閲待ち）
- `ru`: ロシア語（ChatGPT訳の初稿完成。ロシア語話者による校閲待ち）

v1.0.3では現行の学生向けMarkdownに言語切替リンクを追加した。これは既存の練習・課題翻訳を現行の日本語版へ同期したことを意味しない。ロシア語・ウズベク語の練習・課題には旧内容が残るため、採点に使う要件は日本語版で確認する。[既存Labの更新手順](../../../lab/UPDATE_EXISTING.md)だけは3言語の同内容ページを用意した。

言語リンクは各ページの見出し直後に、日本語・ロシア語・ウズベク語の順で置く。教材PDF・HTMLの生成時にはリンク行を除外する。対応先の存在、相対リンク、更新手順のコマンド一致は`2026/lab/tests/test-language-links.py`で確認する。互換用の`2026/v1.0.0/`は編集対象にしない。

## 同期単位

現存する日本語・ウズベク語・ロシア語の3言語で、章ファイル名、章番号、見出し順、図番号、表番号を対応させる。英語版を追加する場合も同じ規則を使う。コマンド、オプション、パス、ユーザー名、グループ名、サービス名、ポート番号、チェックID、URLは翻訳しない。

## 更新手順

1. 現在の翻訳元である日本語版を確認する。
2. `manifest.json`の翻訳元と状態を更新する。
3. `terminology.csv`で訳語を確定する。
4. 日本語、ウズベク語、ロシア語を章単位で更新する。
5. コードブロックと識別子が現行の翻訳元と一致することを自動確認する。
6. 各言語のHTML/PDFを生成して目視確認する。
7. 確認済みの言語だけを`approved`にする。

## 日本語

日本語表記は[`japanese-style-guide.md`](./japanese-style-guide.md)に従う。初学者向けの明確さと、他言語へ対応付けやすい一貫した用語を両立する。

## ウズベク語

ウズベク語版はChatGPTで翻訳し、[`uzbek-style-guide.md`](./uzbek-style-guide.md)と[`terminology.csv`](./terminology.csv)に従う。技術用語は英語表記を保ち、意味をウズベク語で説明する。本文12章・巻末・練習P0～P6・課題M1～M7・参照資料・図21点の初稿は現行日本語版に内容を同期した。構造照合とPDF表示確認を実施しても、ウズベク語話者による校閲が終わるまでは`approved`にしない。

## ロシア語

ロシア語版はChatGPTで翻訳し、[`russian-style-guide.md`](./russian-style-guide.md)と[`terminology.csv`](./terminology.csv)に従う。ウズベク語版の「IT用語を英語のまま保つ」規則を流用せず、定着したロシア語の専門用語を使う。固有名詞、コマンド、パス、IDは原文のまま保つ。本文12章・巻末・練習P0～P6・課題M1～M7・参照資料・図21点の初稿は現行日本語版に内容を同期した。ロシア語話者の校閲まで`approved`にしない。
