# Первоначальная настройка и регистрация в системе проверки заданий

[日本語](student-registration.ja.md) · [Русский](student-registration.ru.md) · [O‘zbekcha](student-registration.uz.md)

Если Lab уже создан, не повторяйте первоначальную установку: используйте [инструкцию по обновлению существующего Lab](../UPDATE_EXISTING.ru.md).

**Выполните команду преподавателя и откройте свою панель прогресса — на этом первоначальная регистрация завершена.** Вы создадите учебный сервер и свяжете его со своим адресом электронной почты из Google Classroom в системе проверки заданий преподавателя. Практическое задание P0 выполняется после регистрации.

Инструкция предназначена для первой настройки. Если вы уже выполняете задания, не запускайте команду установки повторно: используйте раздел «Если возникла проблема».

## 1. Запустите Learner Lab

Если вы ещё не зарегистрированы в AWS Academy, сначала выполните [инструкцию регистрации и входа](https://github.com/ShinyaHaga0910/Introduction-CyberSecurity/blob/main/orientation/aws-academy/README.md).

Откройте Learner Lab, указанный преподавателем, и нажмите `Start Lab`. Дождитесь зелёного индикатора AWS, затем нажмите `AWS`, чтобы открыть консоль AWS.

## 2. Откройте CloudShell

В консоли AWS выберите регион, указанный преподавателем, и откройте CloudShell. Дождитесь готовности командной строки.

Все следующие действия выполняются **в CloudShell**. В этой инструкции подключаться к серверу Ubuntu не нужно.

## 3. Выполните команду преподавателя

Откройте в Google Classroom **команду установки для текущего семестра**. Скопируйте её целиком, вставьте в CloudShell и нажмите Enter.

Адрес системы преподавателя и ключ первоначальной регистрации уже включены в команду. Изменять их самостоятельно не нужно. Используйте именно команду из Google Classroom.

Установка последовательно создаёт учебный сервер, настраивает Ubuntu и регистрирует сервер в системе преподавателя. Дождитесь завершения; не запускайте ту же команду одновременно в другом окне.

## 4. Введите свой адрес электронной почты

Во время установки появится приглашение:

```text
Classroom email (visible):
```

Введите **свой адрес электронной почты Google Classroom с окончанием `@jdu.uz`** и нажмите Enter. Адрес виден на экране; пустой ввод и другой домен не позволяют продолжить. Проверьте показанный адрес, затем введите `Yes` и нажмите Enter. Если адрес неверный, нажмите только Enter и введите его заново. Пароль не требуется. Не публикуйте снимок экрана с адресом.

Преподаватель использует этот адрес, чтобы сопоставить ваш сервер и результаты заданий. Отдельно отправлять Server ID в Google Classroom не требуется. Эта операция не подтверждает владение почтовым адресом, поэтому внимательно проверьте ввод.

## 5. Убедитесь, что настройка завершилась успешно

Должны появиться обе строки:

```text
PASS Teacher registration, EC2 identity, and email link confirmed.
PASS The AWS lab environment is ready.
```

Первая подтверждает регистрацию сервера и привязку почтового адреса, вторая — готовность учебной среды. Если появилась ошибка или одной из строк нет, настройка ещё не завершена.

## 6. Откройте свою панель прогресса

Выполните в CloudShell. После подключения командой `ssh jdu-ubuntu` ту же команду можно выполнить и на сервере Ubuntu. При новой установке она добавляется туда автоматически:

```bash
jdu-my-progress
```


Нажмите на выведенную ссылку. Если она не открывается нажатием, скопируйте HTTPS-адрес в браузер. CloudShell и удалённый сервер Ubuntu не могут автоматически открыть браузер на вашем компьютере. Это **ваша личная панель прогресса**. Страницу предоставляет система преподавателя; на ней отображаются только ваши результаты. Создавать отдельный сервер для панели не нужно.

На странице можно проверить прогресс по P0–P6 и M1–M7. Сразу после регистрации результаты ещё не отправлены, поэтому пустые ячейки или «—» являются нормальными. В заголовке показаны зарегистрированный адрес электронной почты и Server ID. Кнопки в верхней части страницы позволяют выбрать японский, узбекский или русский язык. Имя хоста и EC2 instance ID не отображаются.

Если кнопок выбора языка нет, сервис прогресса преподавателя работает на прежней версии. Повторная установка студенческой команды это не исправит; сообщите преподавателю.

Ссылка действует 15 минут. Когда срок истечёт, снова выполните `jdu-my-progress` в CloudShell или Ubuntu и откройте новую ссылку. Устанавливать сертификат на свой компьютер не требуется.

Если на ранее созданном сервере Ubuntu появляется `jdu-my-progress: command not found`, **после подключения к Ubuntu по SSH** один раз выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/ShinyaHaga0910/OS-Linux-Control/main/2026/lab/scripts/install-my-progress-ubuntu.sh -o /tmp/jdu-install-my-progress-ubuntu.sh
bash /tmp/jdu-install-my-progress-ubuntu.sh
jdu-my-progress
```

Задания и их результаты не сбрасываются. Откройте выведенную ссылку в браузере и никому её не передавайте. Если регистрационные данные Ubuntu недоступны, проверьте, что вы вошли как `ssm-user`, затем обратитесь к преподавателю.

## Проверка завершения

- Появились обе строки успешной настройки с `PASS`.
- Открылась ваша личная панель прогресса.

После обеих проверок первоначальная регистрация завершена. Далее переходите к [инструкции P0](../GUIDED_PRACTICE.md#p0-environment-and-os). Сама регистрация не означает, что P0 выполнено.

## Если возникла проблема

| Ситуация | Действие в CloudShell |
| --- | --- |
| Адрес не введён или указан неверно | Выполните приведённую ниже команду повторной регистрации почты в том же CloudShell |
| Нужно повторно проверить регистрацию | Выполните `jdu-register` |
| Ссылка на панель больше не действует | Выполните `jdu-my-progress` |
| Установка или регистрация завершилась ошибкой | Сообщите преподавателю номер шага и ошибку. Не удаляйте стек самостоятельно |

Не публикуйте и не передавайте ключ регистрации из команды, закрытые ключи, токены доступа и личную ссылку на панель. После работы на общем компьютере закройте страницу панели.

### Повторно зарегистрировать только почтовый адрес

Не запускайте первоначальную команду установки повторно. В **том же CloudShell**, где выполнялась первоначальная настройка, выполните команду ниже. Она позволит изменить только почтовый адрес. Учебный сервер и задания не сбрасываются.

```bash
jdu-register --change-email
```

Введите адрес с окончанием `@jdu.uz` и подтвердите его словом `Yes`. Строка `PASS Teacher registration, EC2 identity, and email link confirmed.` означает успешное завершение. Если регистрационные данные не найдены, проверьте CloudShell и обратитесь к преподавателю.

Если в старой среде команда `jdu-register` отсутствует или не поддерживает `--change-email`, выполните в том же CloudShell следующие команды. SHA-256 проверяется до установки новой версии. Если проверка не пройдёт, инструмент не будет заменён.

```bash
curl -fsSL https://raw.githubusercontent.com/ShinyaHaga0910/OS-Linux-Control/main/2026/lab/scripts/register-student.py -o /tmp/jdu-register-new && \
curl -fsSL https://raw.githubusercontent.com/ShinyaHaga0910/OS-Linux-Control/main/2026/lab/SHA256SUMS -o /tmp/jdu-register-checksums && \
awk '$2 == "scripts/register-student.py" {print $1 "  /tmp/jdu-register-new"}' /tmp/jdu-register-checksums | sha256sum --check --status && \
install -D -m 0755 /tmp/jdu-register-new "$HOME/.local/bin/jdu-register" && \
"$HOME/.local/bin/jdu-register" --change-email
```

## Предварительная подготовка преподавателя

До выдачи команды студентам подготовьте или обновите сервер проверки по [инструкции преподавателя](../teacher/README.md). Разместите созданную команду текущего семестра в Google Classroom. После регистрации сопоставление почтового адреса и Server ID можно проверить через `jdu-dashboard` преподавателя.
