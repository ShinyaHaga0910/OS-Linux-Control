# Обновление существующего Lab без удаления стека

[日本語](UPDATE_EXISTING.md) · [Русский](UPDATE_EXISTING.ru.md) · [O‘zbekcha](UPDATE_EXISTING.uz.md)

Эта инструкция предназначена для группы, в которой преподавательский и студенческие Lab уже созданы. Стек CloudFormation удалять не нужно. Студенческий EC2 также не создаётся заново. Первоначальная установка в новом стеке нужна для проверки новых студентов или для занятий следующего года.

При удалении стека можно потерять записи о прогрессе у преподавателя, результаты упражнений студентов и данные подключения. Для этого обновления удаление не требуется. Сначала преподаватель обновляет свой стек, затем каждый студент обновляет свою среду из CloudShell. Перед началом проверьте AWS account и region, с которыми работаете. Решение об обновлении рабочей среды преподаватель принимает отдельно.

## 1. Преподаватель: обновить тот же стек с прежними ключами

Выполните команды в том CloudShell, который использовали при первоначальной настройке преподавательского Lab. В нём должны сохраняться `~/.jdu-teacher/progress.env`, `admin.key` и `registration.key`. Не показывайте и не передавайте содержимое ключей.

```bash
curl -fsSL https://raw.githubusercontent.com/ShinyaHaga0910/OS-Linux-Control/main/2026/lab/teacher/update-existing-teacher.sh -o /tmp/jdu-update-existing-teacher.sh
printf '%s  %s\n' 'cc6cf61fbb2db3457fd70ce60e8c80733be566e7fc72ec91d827faea3611af3a' '/tmp/jdu-update-existing-teacher.sh' | sha256sum --check
bash /tmp/jdu-update-existing-teacher.sh --region us-east-1
```

Если сохранённого стека нет, скрипт остановится. Он не создаёт и не заменяет ключи, а обновляет тот же стек CloudFormation. После успешного выполнения запустите `jdu-dashboard` и проверьте страницу по новой ссылке для просмотра. Не передавайте эту ссылку другим людям.

```bash
jdu-dashboard
```

## 2. Студент: обновить CloudShell и существующий Ubuntu

После завершения обновления преподавателя каждый студент выполняет команды **в CloudShell, использованном при первоначальной установке**. Не выполняйте их после входа в Ubuntu через `ssh jdu-ubuntu`.

```bash
curl -fsSL https://raw.githubusercontent.com/ShinyaHaga0910/OS-Linux-Control/main/2026/lab/scripts/update-existing-cloudshell.sh -o /tmp/jdu-update-existing-cloudshell.sh
printf '%s  %s\n' '890a92f55ce9183fb10eee8c76ba2c32a03d283edb8deac626fec0f3b96b9087' '/tmp/jdu-update-existing-cloudshell.sh' | sha256sum --check
bash /tmp/jdu-update-existing-cloudshell.sh --region us-east-1
```

Скрипт сначала проверяет, что существующий студенческий стек, SSH-подключение и данные регистрации в CloudShell и Ubuntu относятся к одной среде. Затем он сверяет SHA-256 загруженных файлов и обновляет вспомогательные команды CloudShell и команды проверки заданий в Ubuntu. Студенческий CloudFormation не запускается повторно. Файлы упражнений, Server ID, токен, SSH-ключ и адрес отправки прогресса не сбрасываются.

Если электронная почта ещё не зарегистрирована, введите адрес с окончанием `@jdu.uz`, проверьте отображённый адрес и подтвердите его словом `Yes`. Если адрес уже зарегистрирован, он сохраняется. Только студентам, которым нужно исправить адрес, следует после обновления выполнить в CloudShell:

```bash
jdu-register --change-email
```

После обновления подключитесь к Ubuntu и повторно проверьте только необходимые задания. `jdu-check` автоматически отправляет результат преподавателю. `jdu-my-progress` выводит вашу личную ссылку для просмотра одной строкой. Не передавайте её другим людям.

```bash
ssh jdu-ubuntu
command -v jdu-my-progress
jdu-check P0
jdu-my-progress
```

Если для P3 или M3 появляется `REVIEW`, скрипт не смог безопасно определить прежнее состояние остановленных процессов. Уже выполненные упражнения автоматически не сбрасываются. Только для незавершённого задания выполните на Ubuntu `jdu-reset P3` или `jdu-reset M3`.

## Чего делать не нужно

- Удалять существующий преподавательский или студенческий стек CloudFormation.
- Повторно запускать первоначальный `install.sh` у студентов.
- Заменять регистрационный ключ преподавателя при обычном обновлении.
- Требовать повторного ввода электронной почты от всех студентов. Исправляйте только пропущенный или неверный адрес.

Если первая установка завершилась состоянием `ROLLBACK_COMPLETE` ещё до начала работы, потребуется отдельная процедура восстановления. Не смешивайте её с обновлением действующей учебной среды.
